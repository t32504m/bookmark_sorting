# ステップ1 手順:収集スクリプトのインストールから最初の収集まで

上から順に試してください。各段階の「正しく動いていれば」と違う表示が出たら、そこで止めて表示をそのまま貼り付けてください。

> **収集中は、ブックマークの解除をしないでください**(要件定義書 4.1)。
> 記録はx.comのサイトデータ(IndexedDB)に入っています。ログアウトやサイトデータの消去で消える可能性があるため、**収集の区切りごとに「JSONL書き出し」をしてください**。

## 1. 準備

1. 使うブラウザとその版をメモします(Chromeなら `chrome://version`、Firefoxなら「ヘルプ → Firefoxについて」)。
2. Violentmonkeyを入れて、その版もメモします。これは11節の「使うブラウザと拡張機能」を決める材料になります。
   - 未検証:ChromeではMV2拡張機能の扱いが変わっているため、Violentmonkeyが入らない、または動かない場合があります。その場合はFirefoxを使うか、状況を知らせてください。
3. twitter-web-exporterなど、同じように通信を横取りする他のスクリプトを入れている場合は、切り分けのため無効にしておきます。

## 2. スクリプトを入れる

1. Violentmonkeyのダッシュボードを開き、「+」から「新規」を選びます。
2. 最初から入っている中身をすべて消し、`userscript/x-bookmark-collector.user.js` の内容を丸ごと貼り付けて保存します。
3. 一覧に「X Bookmark Collector」が表示され、有効になっていれば導入は完了です。

## 3. 最初の読み込みを拾えているか確かめる

1. `https://x.com/i/bookmarks` を開きます。すでに開いている場合は再読み込みしてください。
2. 画面の左下に、黒いパネルが表示されます。

**正しく動いていれば**(数秒後):

```
状態: 停止
投稿数(重複除外・累計): 20 前後
  この収集で届いた分: 0
応答数(累計): 1
最後に届いた投稿: 2025-xx-xx xx:xx
  (本文の冒頭)
観測: graphql 数件 / Bookmarks 1 件
```

- 「最後に届いた投稿」は、最初に読み込まれた一まとまりの末尾の投稿です。上から20件目前後に、同じ投稿があるはずです。
- 「警告:」「エラー:」の行が出ていないことを確認します。

**そうでない場合**(表示をそのまま貼り付けてください):

| 表示 | 考えられる原因 |
| --- | --- |
| パネル自体が出ない | スクリプトが動いていない(有効化、`@match`、URLを確認) |
| `graphql 0 件 / Bookmarks 0 件` | 横取りが効いていない。ページの文脈に注入されていないか、Xがfetchに移った。 |
| `graphql` は増えるが `Bookmarks 0 件` | 操作名が `Bookmarks` ではない(未検証の推測が外れた) |
| `警告: ページの文脈で動いていない可能性` | CSPのため、content文脈に落ちている([TWE issue #19](https://github.com/prinsss/twitter-web-exporter/issues/19)と同じ状況)。Violentmonkeyの設定で注入モードを確かめる |
| `Bookmarks 1 件` なのに投稿数が 0 | 応答の構造の推測が外れた。この場合も応答自体は保存されているので、JSONLを書き出して知らせてください |

## 4. 約100件で保存漏れがないか確かめる

1. パネルの「開始」を押します。Endキーを1秒未満に3回押したときと同じように、画面の一番下へ移動します。新しい投稿が届くたびに、1〜3秒おいてから同じ動きを繰り返します。届かなければ5秒ごとに繰り返します(v0.3.0以降)。
2. 「この収集で届いた分」が100を超えたら「停止」を押します。
3. 「JSONL書き出し」を押すと `raw_日時_Nres.jsonl` がダウンロードされます。これをリポジトリの `raw/` フォルダへ移します。
4. 次を実行します。

```
python tools/check_raw.py
```

**正しく動いていれば**:

- 「投稿数(重複除外)」が、パネルの「投稿数(重複除外・累計)」と同じになります。
- 「取り逃しの確認: …直前の応答が記録されていないもの 0 回」と表示されます。
- 「IDが文字列でない投稿: 0」と表示されます。
- 「読めない行: 0 件」と表示されます。
- 画像付き・外部リンク付き・引用付きの件数が、見た印象と大きくずれていません。

5. `name=` の効き方を確かめます。末尾に表示されたURLを、それぞれブラウザで開いてください。
   - `?name=small` と `?name=large` で画像の大きさが変わるか
   - `format=webp` の行で画像が表示されるか

   これを、表示された種類(photo / video / animated_gif)ごとに確かめて結果を知らせてください。GIFの行が出ない場合は、GIF付きの投稿が含まれていなかったということです。

## 5. 最後までスクロールする

1. 「開始」を押して、そのまま待ちます。
2. **区切りごとに「JSONL書き出し」をしてください。** 書き出しは毎回、それまでに記録した全件を含みます。古いファイルを消さずに `raw/` に置いておけば、Python側が重複を除きます。
3. 自動で止まったら、次を行います。
   - 画面の一番下を目で見て、何が表示されているか(読み込み中の表示、エラーの文言、何もない、など)をメモします。
   - 「最後に届いた投稿」の日時と本文を、自分の記憶にある古いブックマークと見比べます。
   - 「記録テキスト」を押して `collect_log_日時.txt` を保存します。
   - もう一度「JSONL書き出し」をして、`python tools/check_raw.py` を実行します。
4. 途中でエラーが出て止まった場合(例:`エラー(HTTP 429)`)は、数分待ってから「開始」を押し直します。**ページを再読み込みしなければ、今の位置から続けられます。** 再読み込みすると先頭からやり直しになりますが、既に記録した投稿は重複として数えられません。
